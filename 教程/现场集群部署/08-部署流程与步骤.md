# 08 · 部署流程与步骤

> **本文是"按什么顺序做"的唯一权威清单。** 每步都给出：**前置条件 → 操作 → 判据 → 命令出处**。
> 目标：出问题时能一眼分层定位（是线的问题、还是配置的问题）。

---

## 0. 三条纪律

| # | 纪律 | 为什么 |
|---|---|---|
| 1 | **线跟着配置走，不要一次把所有线插完** | 业务线插早了，出故障时分不清是线的问题还是配置的问题 |
| 2 | **每轮的判据没过，就不要进下一轮** | 同上的分层原则 |
| 3 | **每个阶段结束必须落盘** —— 交换机/防火墙 `save force`，服务器备份 netplan 与配置文件到 mgmt01 | 单机形态**没有设备级冗余**，配置丢了要重敲 |

> ⚠ 另一条形态纪律：**一期不堆叠，任何 `irf` 开头的命令都不要敲**（含 `irf member` / `irf-port` / `irf-port-configuration active`）。`irf member N renumber M` 一旦 `save force` 就必须 `reboot` 才能回退。

## 2. 现场六轮节奏（拿着走的版本）

| ☐ | 轮次 | 现场动作 | 判据 |
|---|---|---|---|
| ☐ | **1 上架与首配** | 设备上架 → **只接电源与 Console，其余线一根不插** → 加电（S6880 → S5120V3 → MQM8790 → 防火墙）→ 逐台 Console 首配 | **四台都能 SSH**，Console 可拔 |
| ☐ | **2 互联与 WAN** | 插 FW↔S6880（10G）、S6880↔S5120V3 上行（网线 + `1000BASE-T` 光转电模块）、MQM8790 管理口、4 条 WAN → 配 S6880 → 配 S5120V3 → 配防火墙 | FW ping 通两运营商网关；内网口 ping 通 FW；上行两端都 up |
| ☐ | **3 服务器** | 上架 → 接 BMC×10、25G×10、IB×19 → BMC 配管理地址 → 装系统 → netplan 配业务口 | `ping 192.168.11.254` 通 + `ping 223.5.5.5` 通 + 网卡 up 有址 |
| ☐ | **4 IB 算力网** | **先接 Console 确认 MQM8790 命令行形态与 SM 开关方式** → 装 MLNX_OFED → `mlxconfig` 固定 IB → 定 SM 落哪一侧 → 配 IPoIB（如需） | `ibstat` 全 Active / 200 Gb/s；`ib_write_bw` ≥ 190 |
| ☐ | **5 发布与验收** | NAT Server + 安全策略（`service-port`）→ 智能 DNS → 跑全量验证清单 → 安全加固 + `save` | 外部能访问 `.166:443`；清单全过 |
| ☐ | **6 客户远程接入** | 确认授权 → 地址池 / 隧道接口 / SSL 网关 → ACL 3999 + route-list + policy-group → 客户账号 → 安全策略 → **两台交换机各加回程路由** | 客户端 iNode 拿到 `192.168.99.x` 后：ping 管理网通、能开 BMC、能 ssh 业务网 |

> **服务器集群服务（阶段 6）可并行推进**：它只依赖阶段 2/3/5，不依赖阶段 7/8/9。实际执行时就是在"轮次 3"完成网络后紧接着做。

## 3. 阶段 0 · 准备与 Console 首配

### 前置
- 硬件到货、机柜到位、走线规划完成（见 [10-附录A](./10-附录A-物料与接口适配.md)）
- Console 线 ×2、笔记本（装 PuTTY/SecureCRT + USB 串口驱动）
- **出发前必做**：把 `1000BASE-T` 光转电模块插到 S6880 `1/0/48`、另一端网线接 S5120V3 `1/0/48`，确认 `25GE1/0/48` 能否 up
  → ✅ **2026-09-24 已实测通过（UP@1G）**，该前置验证卡点已消除

### 操作
1. 上架（建议从上到下：防火墙 → S6880 → S5120V3 → MQM8790 → 服务器），电源分接两路 PDU。
2. **先不插业务线**，只接电源和 Console。
3. 加电顺序：**S6880 → S5120V3 → MQM8790 → 防火墙**。
4. 逐台 Console 首配（9600 8N1）：admin 账号 + SSH + 管理 IP。命令见 `04 篇 §2`（S6880）、`03 篇 §4`（S5120V3）、`04 篇 §1`（防火墙）。
   MQM8790 用 Onyx 命令：`enable` → `configure terminal` → `interface mgmt0` → `ip address 192.168.10.252 /24` → `no shutdown` → `username admin password 0 <口令>` → `save`。

### 判据
**四台都能 SSH**（管理 SSH 不依赖防火墙与外网，只要笔记本与设备管理 IP 三层可达）：
- S6880：笔记本直插它的 M-GE 带外口，笔记本配 `192.168.9.100/24` → `ssh admin@192.168.9.250`
- S5120V3：插它任意一个下联口（`GE1/0/1`–`1/0/10` 已是 VLAN 10），笔记本配 `192.168.10.110/24` → `ssh admin@192.168.10.251`
- 防火墙：插它的管理口（丝印 `MGE1/0/0`），笔记本配 `192.168.10.110/24` → `ssh admin@192.168.10.253`

> ⚠ 笔记本**必须插网线**。只连 Wi-Fi（含手机热点）时笔记本上不存在对应网段的路由，SSH 必然 `Connection timed out`。
> ⚠ 四台设备开工前都用 `display interface brief` 核对实际接口名再套命令。

## 7. 阶段 4 · 防火墙基础配置

### 前置
阶段 2 完成（内网口对端已就绪）；4 条 WAN 线已插（面板 0–3）。

### 操作（四步走）
1. **接口**：`port link-mode route` → IP → `undo shutdown`（`GE1/0/1` 电信 `.165`、`GE1/0/2` 联通 `.156`、`GE1/0/0`/`1/0/3` 不配 IP、`XGE1/0/26` 内网口 `.254.1`）

3. **NQA + Track + 浮动路由**：两条 `nqa entry`（`ctline`/`culine`）→ `nqa schedule`（**系统视图**）→ `track 1/2`（**每条后 `quit`**）→ 两条缺省路由（`track N` 必须在 `preference` **前**）→ 回程明细路由 `192.168.0.0/16`
4. **NAT outbound + 基础安全策略 4 条**：ACL 3000 + `nat outbound`；`LAN-to-WAN` / `Local-to-LAN` / `Local-to-WAN` / `LAN-to-Local`

（完整命令见 [04 篇](./04-防火墙-F1000-AI-25.md) §2–§7.1）

### 判据
| 检查 | 命令 | 预期 |
|---|---|---|
| 到内网 | `ping 192.168.254.2` | 通（**实测 5/5、0% 丢包**） |
| 到电信网关 | `ping -a 60.191.84.165 60.191.84.161` | 通 |
| 到联通网关 | `ping -a 101.71.15.156 101.71.15.153` | 通 |
| 到公网 | `ping 223.5.5.5` | 通（**实测 RTT 2.7 ms**） |
| NQA / Track | `display nqa result` / `display track 1` | 有数据、**Positive** |
| 缺省路由 | `display ip routing-table` | pref 60（电信）生效 |
| **主备切换演练** | 拔掉电信主线 | **秒级切联通、回插自动回切（已实测通过）** |

## 8. 阶段 5 · 服务器以太网

### 前置
阶段 2/3 完成；服务器上架、接线（BMC×10、25G×10）。

### 操作
1. **BMC 配管理地址**：网页 `https://192.168.10.<尾号>` 或 ipmitool；网关 `192.168.10.254`；**不配 VLAN ID**。
2. **装系统**：Ubuntu（实测 22.04.5），统一镜像。
3. **业务口 netplan**（单口；两种网段都要配齐的话见 [05 篇 §4.1](./05-服务器与集群服务.md)）：

```yaml
network:
  version: 2
  ethernets:
    enp1s0f0:
      addresses: [192.168.11.11/24]
      routes: [{ to: default, via: 192.168.11.254 }]
      nameservers: { addresses: [223.5.5.5, 114.114.114.114] }
```
```bash
sudo netplan try && sudo netplan apply
```

### 判据
| 检查 | 预期 |
|---|---|
| `ip -br addr show` | 业务网卡 up、地址生效 |
| `ping 192.168.11.254` | 通 |
| `ping 223.5.5.5` | 通（FW 会话表可见 NAT 条目） |
| 10 个 BMC | 管理网可访问、能开登录页（**`https://`**） |

> ⚠ **"网卡 up 但上不了网"最常见的原因就是插错口**：只有 `1/0/1`–`1/0/12` 是 access VLAN 11；插到 `1/0/13`–`1/0/46`（预留区）落在 **VLAN 1，没有网关**。
> 排查顺序：S6880 上 `display interface brief` 找 **UP 的那个口** → `display vlan` 看它属于哪个 VLAN → 不在 VLAN 11 就换口或把该口划进来。

## 9. 阶段 6 · 服务器系统与集群服务

### 前置
阶段 5 完成（业务网互通）；已有 mgmt01 → 各节点 SSH 免密。

### 操作顺序（**stg01 必须最先**，它是 NFS 服务端）
1. **基础环境**：关 ufw、提 limits、关 swap
2. **主机名**：`mgmt01` / `stg01` / `gpu01`–`gpu08`（gpu 两位数字）
3. **`/etc/hosts`**：清旧残留 → 写业务网 10 行全集 → 修 `127.0.1.1`
4. **chrony**：mgmt01 为源（`allow 192.168.11.0/24`），其余 9 台指向 `mgmt01`
5. **NFS**：stg01 导出 `/mnt/sdb`（限 `192.168.11.0/24`）+ 本机 bind `/shared`；其余 9 台挂 `stg01:/mnt/sdb /shared`
6. **MUNGE**：mgmt01 生成 key → base64 分发到 9 台 → 校验 sha256 一致
7. **Slurm**：mgmt01 编译 24.11.6 → 打包 scp → 各节点解包 → 建 slurm 用户与目录 → 写 systemd 单元
8. **配置文件**：`slurm.conf`（每台一致）、`gres.conf`（仅 gpu）、`cgroup.conf`（每台）
9. **启动**：mgmt01 先 `slurmctld`，再各台 `slurmd`
10. **记账**：MariaDB → 建库/用户 → `slurmdbd.conf`（`DbdHost=mgmt01`）→ `slurmdbd` → 建 `aiclust` 账户
11. **自愈与加固**：`/run/slurm` tmpfiles、`Restart=on-failure`、mgmt01 免密

> **一键脚本**：`docs/10台服务器/setup-node.sh`（幂等）把 1–5 与 munie/slurm 服务重启一次做完：`sudo bash setup-node.sh <本机名>`。

### 判据
```bash
sinfo                                   # cpu×2 + gpu×8 + cpugpu×8 全 idle
srun -p cpu -N2 -n2 hostname            # mgmt01 / stg01
srun -p gpu -N8 hostname                # gpu01~gpu08
srun -p gpu --gres=gpu:2 sh -c 'echo $CUDA_VISIBLE_DEVICES'   # -> 0,1
sbatch --wrap='srun hostname' -o /shared/slurm-logs/probe-%j.out
sacct -n -X --format=JobID,JobName,State,NodeList
df -hT /shared                          # 每台：stg01:/mnt/sdb 220T
```
> ✅ **2026-09-24 已全部实测通过。** 详见 [09 篇](./09-验证与验收清单.md)。

## 11. 阶段 8 · 对外发布（NAT Server）

### 前置
平台服务已在 `192.168.11.11` 就绪（至少 443 与 22 端口在监听）。

### 操作
```bash
# 7.0 前置：发布 IP 先落到接口上（否则设备不应答其 ARP）
interface GigabitEthernet1/0/1
 ip address 60.191.84.166 255.255.255.248 sub
interface GigabitEthernet1/0/2
 ip address 101.71.15.158 255.255.255.248 sub

# NAT Server（4 条）
nat server protocol tcp global 60.191.84.166 443  inside 192.168.11.11 443
nat server protocol tcp global 60.191.84.166 6022 inside 192.168.11.11 22
nat server protocol tcp global 101.71.15.158 443  inside 192.168.11.11 443
nat server protocol tcp global 101.71.15.158 6022 inside 192.168.11.11 22

# 安全策略（两条，用 service-port）
 rule name WAN-to-Platform-443  ...  service-port tcp destination eq 443
 rule name WAN-to-Platform-6022 ...  service-port tcp destination eq 6022
save force
```

### 判据
- 外部网络访问 `https://60.191.84.166:443` 通
- `display nat server` 可见 4 条映射；`display nat session` 有转换条目
- **公网 DNS 需为同一域名在电信/联通各解析一条 A 记录**（智能 DNS），入站才能按线路分流

## 12. 阶段 9 · 客户远程接入（SSL VPN）

### 前置（缺一不可）
1. **管理网与业务网的物理链路必须先通** —— `Vlan-if10`（需 S5120V3 上行）、`Vlan-if11`（需服务器接入）。**这两条没通之前，VPN 配好了也 ping 不到任何内网地址。**
2. `display license` 确认 SSL VPN 并发数（**F1000-AI 出厂自带 15 个**）。

### 操作（九步）
① 建地址池 → ② 隧道接口 `SSLVPN-AC 1` → ③ SSL 网关 `remotegw`（`.165:4430`）→ ④ `acl advanced 3999` → ⑤ `sslvpn context remote`（route-list + address-pool + policy-group，**`filter ip-tunnel acl 3999` 必配**）→ ⑥ 客户账号 → ⑦ 去内网路由 → ⑧ `security-zone name VPN` → ⑨ 安全策略 5 条 → **两台交换机各加回程路由**。

（完整命令见 [07 篇](./07-客户远程接入-SSLVPN.md) §2–§4）

### 判据
| 检查 | 通过标准 |
|---|---|
| 防火墙侧 | `display sslvpn gateway` Up；`display sslvpn context` Up |
| 入口可达（不依赖内网） | 手机走蜂窝数据打开 `https://60.191.84.165:4430` 出现登录页 |
| 客户端 | iNode 显示「建立VPN隧道成功」并给出 `192.168.99.x` |
| 本机自检 | `route print` 有两条内网路由（192.168.10.0/11.0 → 192.168.99.254） |
| 管理网 | `ping 192.168.10.11` 通；`Test-NetConnection 192.168.10.251 -Port 22` → `TcpTestSucceeded: True` |
| 业务网 | `ssh ps@192.168.11.13` 通 |

> ⚠ 排障顺序：**先看 `acl advanced 3999`（第一道过滤，按目的 IP），再看安全策略**。ACL 没放行的目的 IP，安全策略放行也没用。

## 15. 快速回退

| 故障 | 处置 |
|---|---|
| 单机形态下误敲了 `irf` 命令 | 单台不需要堆叠命令；`irf member 1 renumber` 这类改动只要**没有 `save force`**，`reboot` 即回滚 |
| 某阶段配置敲错 | `save` 之前的错误可重启回滚；已保存则进入对应接口逐条 `undo` |
| 防火墙 WAN 口配 `ip address` 提示命令不存在 | 该口仍是二层模式；先 `port link-mode route` |
| 防火墙切到备线不回切 | `display track all` 看状态；NQA 失败多为 `action-type` 没写 `trigger-only`，或 `nqa schedule` 没在系统视图下发 |
| NAT Server 生效但外部访问不通 | 安全策略里 `service` 写成了裸端口名；改用 `service-port tcp destination eq <端口>` |
| 大帧命令报 Unrecognized | `jumboframe enable` 发在了系统视图（它是接口级命令，且默认已允许 9216 字节） |
| 配置丢失 | 单机无冗余 —— 从离线备份恢复；平时每阶段 `save force` |
