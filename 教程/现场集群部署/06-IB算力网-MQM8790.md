# 06 · IB 算力网 MQM8790-HS2F

> **设备角色**：InfiniBand fabric 核心，承载 GPU 间 **RDMA/NCCL** 计算通信。
> **完全独立部署**：无以太网网关、不与管理网/业务网互联，不存在跨网访问路径。
> **配套**：《配置命令执行手册.md》阶段 6；《HPC集群网络配置方案.md》§6。

## 1. 设备概况

| 项 | 值 |
|---|---|
| 型号 | NVIDIA（Mellanox）**MQM8790-HS2F** |
| 端口 | **40 × QSFP56 200G HDR** |
| 管理 | **`mgmt0`** = 192.168.10.252/24，网线接 S5120V3（VLAN 10），仅管理用 |
| 软件体系 | NVIDIA Onyx（`enable` → `configure terminal`，与 H3C 完全不同） |
| 归属档位 | ⚠ NVIDIA 产品线里属 **unmanaged** 档（对照 managed 的 `MQM8700-HS2F`），规格上带 x86 双核 + 板载 SM（约 2000 节点），但**可能没有完整 Onyx 命令行** |
| 服务器侧网卡 | **MCX653106A-HDAT**（ConnectX-6 VPI，HDR200，PCIe 4.0 x16） |
| fabric 地址规划 | `10.20.0.0/16`（IPoIB 规划值，**本项目未配置且不需要**） |

### 1.1 通信路径定稿（2026-09-24）

| 通信 | 走哪个网 | 依据 |
|---|---|---|
| **Slurm 管理**（`slurmctld` ↔ `slurmd`、srun RPC、`slurmdbd` 记账、`munge`） | **业务网 `192.168.11.0/24`（25G 以太网）** | 管理流量小、要低延迟不要求大带宽，25G 富余；**且不依赖 IB 的 SM** |
| **NFS 存储**（`stg01:/mnt/sdb` → 各机 `/shared`） | **同为业务网 25G** | 220T RAID5（HDD）顺序读写约 1–2 GB/s，而 25G 链路提供 3.1 GB/s ⇒ **瓶颈在磁盘不在网络**，改走 IB 无收益 |
| **IB `10.20.0.0/16`** | 只用于 **MPI 计算通信**，走 **IB verbs / RDMA（不经 IP）**，**不是 IPoIB** | HPC 标准做法：带宽更高、延迟更低、CPU 占用近零 |

> **一句话**：`/etc/hosts` 里**只写业务网地址**，Slurm 与 NFS 全部基于它工作；IB 是给 MPI 的，两者互不干扰。

## 3. 服务器侧网卡配置（阶段 6.1 / 6.2）

```bash
# 6.1 安装 MLNX_OFED（先装驱动才有 mlxconfig / mst 工具）
apt install -y linux-headers-$(uname -r) build-essential dkms
./mlnxofedinstall --force
reboot

# 6.2 固定 IB 模式（MCX653106A-HDAT 出厂可能为 ETH 模式；LINK_TYPE 改动需重启生效）
mst start
mlxconfig -d /dev/mst/mt4123_pciconf0 q        # 先查询：确认设备与端口数
mlxconfig -d /dev/mst/mt4123_pciconf0 s LINK_TYPE_P1=1 LINK_TYPE_P2=1
# 注意：mgmt01 若为单口卡，只设 LINK_TYPE_P1=1，设 P2 会报错
reboot
```

✅ **实测状态（2026-09-24）**：MLNX_OFED **24.10** 已装，各节点 **4 个 HCA 全识别**；200G 口已固定为 IB 模式且 `ACTIVE`。

### 3.1 ⚠ IB 设备编号因机而异

| 节点 | IB 卡设备号 | 25G 业务网卡设备号 |
|---|---|---|
| **mgmt01** | **`mlx5_0`** | `mlx5_2` |
| **gpu01–08 / stg01** | **`mlx5_2`** | `mlx5_0` |

> **用 `ibstat -l` 先确认，别照抄 `-d mlx5_0`。** IPoIB 口名同样不统一（mgmt01 = `ibs2f0`、gpu01 = `ibP1p129s0f0`）。

## 4. Subnet Manager（阶段 6.3）

**一个 fabric 只允许一个 SM。**

```
apt install -y opensm
# /etc/opensm/partitions.conf ← 见 §5
systemctl enable --now opensmd
```

✅ **已实施（2026-09-24 实测）**：

| 项 | 值 |
|---|---|
| SM 所在节点 | **mgmt01**（`opensmd` service **active**，17:47 启动） |
| SM GUID | `0x5000e60300f50ce8` —— **正是 mgmt01 `mlx5_0` 的 Node GUID** |
| `sminfo` state | **`SMINFO_MASTER`** |
| 结论 | **fabric 内只有这一个 SM 生效，无双 SM 冲突** |
| LID 分配 | mgmt01 = 1、gpu01 = 3、gpu02 = 5 …… |

> ⏳ **仍建议**：登录 MQM8790 复核**板载 SM 是否物理关闭** —— 若它也在跑，交换机重启后可能抢权造成双 SM。
> ⚠ 若板载 SM 关不掉（unmanaged 档可能没有 `no ib sm` 命令），则**只保留板载 SM、不启 opensmd**；但那样下面的 `partitions.conf`（PKey 隔离）就无法由主机侧下发，需改用交换机侧或 UFM 配置分区。

## 5. Partition（PKey）规划

| PKey | 名称 | 成员 | 用途 |
|---|---|---|---|
| `0x7fff`（默认） | compute | 全部节点（含 mgmt01） | NCCL/RDMA 计算流量 |
| `0x0100` | storage | 存储节点 + 全部计算节点 + **mgmt01** | 存储数据流量（与计算同 fabric 复用、逻辑隔离） |

`/etc/opensm/partitions.conf`：

```
Default=0x7fff: ALL, ALL_SWITCHES=full;
Storage=0x0100, defmember=full: ALL;
```

> 规划意图是把"计算流量"与"存储流量"在同一 fabric 上做逻辑隔离（对应原设计图里的"存储流量复用，Partition 隔离"）。
> ⚠ 现状：IPoIB 未配、双平面未实施 ⇒ **PKey 隔离尚未启用**，当前 fabric 是单一默认分区。

| **NCCL** | ❌ **未安装**（`libnccl.so` 不存在） |

**⇒ 现在"计算走 IB"跑不起来，不是网络问题，而是没有能利用 IB 的程序。装好即自动走 IB，Slurm 与 NFS 配置一个字都不用改。**

装好后怎么用：

```bash
# 每台安装
sudo apt install -y openmpi-bin libopenmpi-dev

# 提交时让 OpenMPI 走 UCX → 自动选 IB verbs（无需 IPoIB）
srun -p gpu -N2 --gres=gpu:8 mpirun --mca pml ucx ./my_mpi_program

# NCCL（PyTorch 分布式）：装好后自动优先选 IB，无需额外参数
NCCL_DEBUG=INFO python train.py     # 日志里应出现 NET/IB
```

> ⚠ `MpiDefault` 当前为空 ⇒ 直接用 `srun` 启动 MPI 需显式 `--mpi=pmix`，**建议用 `mpirun`**。
> ⚠ 程序里**别写死设备号**（IB 卡编号因机而异，见 §3.1）。

## 9. 本篇相关坑

1. **IB 设备编号因机而异** —— 别写死 `-d mlx5_0`，先 `ibstat -l`。
2. **IPoIB 口名不统一** —— mgmt01 = `ibs2f0`、gpu01 = `ibP1p129s0f0`，别写 `ib0`。
3. **netplan 没有 `ibs:` 顶层关键字** —— IPoIB 口要放 `ethernets:` 段并加 `infiniband-mode`（本项目不需要配）。
4. **VPI 卡出厂可能是 Ethernet 模式** —— 必须 `mlxconfig` 固定 IB 并重启。
5. **一个 fabric 只允许一个 SM** —— 双 SM 会互相抢权（当前已确认单 SM，但板载 SM 待复核）。
6. **IB 口起不来先查三处**：`mlxconfig` 的 LINK_TYPE、线缆是否 NVIDIA 认证 HDR、交换机端口状态。
7. **非认证线在 HDR 速率下易误码** —— 必须用 NVIDIA 认证型号。
