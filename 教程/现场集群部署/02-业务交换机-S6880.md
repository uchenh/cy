# 02 · 业务交换机 S6880-48Y8C

> **设备角色**：全网**唯一三层网关** + 服务器 25G 接入 + 上联防火墙出口。
> **配套**：《配置命令执行手册.md》阶段 0 / 1 / 2 / 8；《HPC集群网络配置方案.md》§3。

---

## 1. 设备概况

| 项 | 值 |
|---|---|
| 型号 | H3C **S6880-48Y8C** |
| 物理端口 | **48 × 25G SFP28 + 8 × 100G QSFP28**（**没有千兆电口**） |
| 软件体系 | Comware 7（H3C 交换机命令） |
| 数量 | **1 台（单机，不堆叠）** |
| 主机名 | `Core_SW`（执行手册阶段 2 的 `sysname`） |
| 管理地址 | `Vlan-interface10` = **192.168.10.254/24**（同时是管理网网关） |
| 带外地址 | `M-GigabitEthernet0/0/0` = **192.168.9.250/24**（独立网段，仅笔记本直连） |
| 承担的功能 | ① 管理网网关 ② 业务网网关 ③ 服务器 25G 接入 ④ 上联防火墙 ⑤ trunk 到管理交换机 ⑥ VPN 回程路由 |

> ⚠ **100G 口在显示里会被缩写成 `GE1/0/49`**（`display interface brief` 输出），极易误读成 GigabitEthernet。配置时 100G 写 **`HundredGigE1/0/x`**，10G 口才是长名 `Ten-GigabitEthernet`。判据：`display interface ?`。

## 2. 接口配置（逐项）

### 2.1 三层网关接口

```
interface Vlan-interface10
 ip address 192.168.10.254 255.255.255.0
 description MGMT-GW
quit
interface Vlan-interface11
 ip address 192.168.11.254 255.255.255.0
 description BIZ-GW
quit
```

| 接口 | IP | 用途 | 备注 |
|---|---|---|---|
| `Vlan-interface10` | 192.168.10.254/24 | 管理网（BMC）网关 + **本机管理地址** | 客户经 VPN 即用这个地址 SSH 本机 |
| `Vlan-interface11` | 192.168.11.254/24 | 业务网网关 | 10 台服务器的默认网关 |

> ⚠ **带外口不能配 192.168.10.x**：S6880 自己就是 `Vlan-if10` 网关，H3C **不允许同一台设备的两个三层接口落在同一网段**，若带外口占着 `192.168.10.250/24`，配 `Vlan-interface10` 时会报
> `This subnet overlaps with another interface!`，**管理网关直接配不上**（2026-09-23 现场实测）。
> 若已踩到，按下述改回：
> ```
> interface M-GigabitEthernet0/0/0
>  undo ip address
>  ip address 192.168.9.250 255.255.255.0
> quit
> interface Vlan-interface10
>  ip address 192.168.10.254 255.255.255.0
> ```
> 配完 `display ip interface brief` 应看到 `MGE0/0/0 = 192.168.9.250`、`Vlan10 = 192.168.10.254`（两者必须不同网段）。

### 2.2 上联防火墙（route 口）

```
interface Twenty-FiveGigE1/0/47
 port link-mode route
 speed 10000
 ip address 192.168.254.2 255.255.255.252
 description TO-F1000AI25
 undo shutdown
quit
```

| 项 | 值 |
|---|---|
| 物理介质 | SFP28 口插 **10G SR 多模模块**（FINISAR `FTLX8574D3BCL`，850nm）+ OM3/OM4 多模 LC 跳线 |
| 速率 | **强制 10000**（SFP28 向下兼容 SFP+，两端原生 10G） |
| 互联网段 | `192.168.254.0/30`，本端 `.2`、防火墙 `192.168.254.1` |
| 是否落 VLAN | **否** —— 这是 route 口，不参与 VLAN |

> ⚠ 850nm 只能配**多模**跳线，不能用单模黄纤。

### 2.3 trunk 到管理交换机（单链路）

```
interface Twenty-FiveGigE1/0/48
 speed 1000
 port link-type trunk
 port trunk permit vlan 10 11
quit
```

| 项 | 值 |
|---|---|
| 本端 | S6880 `1/0/48`（SFP28 口，插 **`1000BASE-T` 光转电模块** → 变 RJ45） |
| 对端 | S5120V3 `GigabitEthernet1/0/48`（**千兆电口**），中间普通网线 |
| 速率 | **只能 1G**，本侧显式 `speed 1000` |
| 放行 | VLAN **10 和 11** 都必须 permit |

**为什么必须走"光转电"**：S6880 全是光口（25G/100G），而 S5120V3-52P-SI 的 4 个 SFP 口是 **1000BASE-X 千兆**、不支持万兆（同系列带 1G/10G SFP+ 的是 `52S-SI`）。两端唯一可行的交汇点是"S6880 用光转电模块变电口 ↔ S5120V3 的千兆电口"。

> ✅ **2026-09-24 实测结论**：模块到货插入后 `25GE1/0/48` **UP、速率 1G**，`Vlan10` 随之 up ⇒ **管理网打通**。原退路（换 `52S-SI`）不再需要。

### 2.4 服务器下联口（access VLAN 11）

```
# 登录节点 mgmt01
interface Twenty-FiveGigE1/0/1
 port link-type access
 port access vlan 11

# 存储节点 stg01
interface Twenty-FiveGigE1/0/2
 port link-type access
 port access vlan 11

# GPU 节点 gpu01–gpu08（一段统一配置）
interface range Twenty-FiveGigE1/0/3 to Twenty-FiveGigE1/0/10
 port link-type access
 port access vlan 11
```

| 端口 | 节点 | IP |
|---|---|---|
| `1/0/1` | mgmt01 | 192.168.11.11 |
| `1/0/2` | stg01 | 192.168.11.12 |
| `1/0/3`–`1/0/10` | gpu01–gpu08 | 192.168.11.13–.20 |
| `1/0/11`–`1/0/12` | 现场扩展服务器口 | 由预留区划入 VLAN 11 |

> **整段统一 VLAN、不绑定具体节点** ⇒ 节点换插口只需换线，**交换机零改动**。
> **端口规则：端口号 = IP 尾号 − 10**（mgmt01→口 1、stg01→口 2、gpu01 起顺延→口 3 起）。
> ⚠ 现场机器实际接在 `1/0/3`–`1/0/12`，故 `1/0/11`、`1/0/12` 已从预留区划入 VLAN 11。**预留区是 `1/0/13`–`1/0/46`**，落在这里的口属于 **VLAN 1 —— 没有网关**（链路 up 但三层不通，是"网卡有址上不了网"的最常见原因）。

## 3. VLAN 与三层路由

```
system-view
sysname Core_SW

vlan 10 11
```

> ⚠ **`vlan 10 11` 是批量建 VLAN，执行后停留在【系统视图】**，后面**不要跟 `quit`** —— 一 `quit` 就退回用户视图，后续命令全部报 `Unrecognized`。

### 3.1 路由表条目

| 目的 | 下一跳 | 说明 |
|---|---|---|
| `0.0.0.0/0` | `192.168.254.1` | 缺省路由指向防火墙 |
| `192.168.99.0/24` | `192.168.254.1` | **SSL VPN 回程路由（必配）**，让 VPN 客户端所在网段的回包交给防火墙 |

```
ip route-static 0.0.0.0 0 192.168.254.1
ip route-static 192.168.99.0 24 192.168.254.1
```

> 直连网段（`192.168.10.0/24`、`192.168.11.0/24`、`192.168.254.0/30`）由接口自动生成，无需静态路由。

### 3.2 大帧（jumbo frame）

| 结论 | 说明 |
|---|---|
| **本方案无需配置** | Comware 7 的 `jumboframe enable [ size ]` 是**接口级**命令（发在系统视图直接报错），且设备**缺省即允许 9216 字节**，已覆盖 9000 的需求 |
| 若确要调整 | 必须在物理口**加入聚合组之前**逐个口下发（加入聚合后不可再改），并与服务器侧 MTU 保持一致 |

## 4. Console 首次配置（阶段 0，每台设备通用流程）

> 新设备出厂无 IP、SSH 未开，**必须用 Console**。终端参数 **9600 8N1 无流控**（乱码改试 115200）。

```
system-view
undo telnet server enable          # 关明文 Telnet（默认本就是关的）
ssh server enable
local-user admin class manage
 password simple <强口令>
 service-type ssh
 authorization-attribute user-role network-admin
quit
line vty 0 63                      # 实测本机支持 0 63；个别型号只有 0–4，报错就改 0 4
 authentication-mode scheme
 protocol inbound ssh
quit
interface M-GigabitEthernet0/0/0
 ip address 192.168.9.250 255.255.255.0
 undo shutdown
quit
save force
```

> - **关 Telnet 是 `undo telnet server enable`**，写成 `telnet server disable` 会报 `Unrecognized command`。
> - 首配里报 `Unrecognized` 的命令**全是安全加固项，跳过不影响业务**。
> - 口令规则：≥10 位、含大小写 + 数字 + 特殊字符。**本项目的实际 admin 口令明文只保存在《配置命令执行手册.md》阶段 0，本目录不复制。**
> - 验证：办公电脑 `ssh admin@192.168.9.250` 能登录 → Console 可拔（笔记本有线网卡配 `192.168.9.100/24`、**网关留空**）。

> ⚠ **ssh 报 `Connection timed out` 的查法**：timeout = TCP 根本没到设备（网络问题），密码错会提示 `Permission denied`，SSH 没开是 `Connection refused`。
> 最常见原因：**笔记本只连 Wi-Fi（含手机热点）而没插网线** —— 笔记本上不存在 192.168.9.0/24 的路由，请求被交给 Wi-Fi 网关发走了。必须插网线直连 S6880 的 M-GE 口；没有 RJ45 就用 USB 转 RJ45。实在没网线时，**先用 Console 把阶段 2 全部敲完**，SSH 验证推迟到接上管理网之后再补。

## 5. 阶段 1（原堆叠阶段）—— 本形态无需配置

现场业务交换机只有 1 台，**不做 IRF、不做 MAD**：

```
display version                  # 记录软件版本号（排查差异时要用）
display interface brief          # 核对 25G 口（1/0/1–48）与 100G 口（1/0/49–56）的实际命名
```

**不要敲任何 `irf` 开头的命令**。原两台堆叠的完整命令与顺序坑（含 `irf-port-configuration active` 与 `save force` 的先后）已归档在《HPC集群网络配置方案.md》§10.4 附录，二期扩到 2 台时照它做。

## 6. 若在端口重排前已配过这台交换机：残留清理

2026-09-23 端口重排把配置整体挪了位置，如之前已按旧端口配过，需要先撤销两处特殊配置：

```
interface Twenty-FiveGigE1/0/1
 undo ip address
 port link-mode bridge        # 从三层口改回二层口
quit
interface Twenty-FiveGigE1/0/2
 undo speed                   # 撤销 1G 降速，恢复 25G
quit
```

之后 `1/0/2` 会被配成 stg01 的 access VLAN 11；`1/0/3`、`1/0/5`–`1/0/10` 本就在 `interface range` 范围内，重复配一遍无副作用。

**残留清理（旧配置会在 `1/0/11`–`1/0/13` 留下 access VLAN 11）**：

```
interface range Twenty-FiveGigE1/0/11 to Twenty-FiveGigE1/0/13
 undo port access vlan 11
quit
```

> ⚠ 注意与 §2.4 的现场扩展**互相冲突**：`1/0/11`、`1/0/12` 现在**确实要用**（机器接在那儿），所以只清理确认不再使用的口（当前实际只需清 `1/0/13`）。判断依据是 `display interface brief` 里哪些口真的 up。

## 7. 验证

| 检查项 | 命令 | 预期 |
|---|---|---|
| VLAN 已建 | `display vlan` | `Total VLANs: 3 / The VLANs include: 1(default), 10-11` |
| 三层接口 | `display ip interface brief` | `Vlan10 = 192.168.10.254`、`Vlan11 = 192.168.11.254`、`MGE0/0/0 = 192.168.9.250` |
| 上联口 | `display interface brief` | `25GE1/0/47` UP、`25GE1/0/48` UP@**1G** |
| 下联口 | `display interface brief` | 已接线口（`1/0/1`–`1/0/12`）UP；未接线口 down 属正常 |
| 路由 | `display ip routing-table` | 缺省路由指向 `192.168.254.1`；`192.168.99.0/24` 指向 `192.168.254.1` |
| 到防火墙连通 | `ping 192.168.254.1` | 通（**实测 5/5、0% 丢包**） |
| 配置落盘 | `save force` | 每次改动后执行 |

> ⚠ **`display vlan` 只列 VLAN 号、不列成员端口**（输出形如 `Total VLANs: 3 / The VLANs include: 1(default), 10-11`）。
> **要看某个 VLAN 的成员端口必须指定 VLAN 号**：`display vlan 11`（列出 Untagged/Tagged 成员）；
> 或看单口：`display current-configuration interface Twenty-FiveGigE1/0/11`。
> 2026-09-24 现场因这条对不上，误以为没配上。

## 9. 本篇相关坑（详见 [11-附录B-现场坑与排障](./11-附录B-现场坑与排障.md)）

1. `vlan 10 11` 后跟 `quit` 会退回用户视图，后续全报 Unrecognized。
2. 带外口与 `Vlan-if10` 同网段 → `This subnet overlaps with another interface!`。
3. `jumboframe enable` 是接口级命令，系统视图下发报错。
4. `display vlan` 不带 VLAN 号看不到成员口。
5. `reset saved-configuration` / `reboot` 属**用户视图**命令，系统视图下敲会报 Unrecognized。
6. Console 串口掉线会吞掉正在粘贴的配置 —— 单次粘贴 ≤10–15 行，每段后复核。
