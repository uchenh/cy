# 附录 B · 现场坑与排障

> 本附录汇总**已实际踩过**的坑（含 H3C Comware 7 通用坑与现场专有坑），以及四套排障流程与快速回退表。
> 每条都标了**现象 → 原因 → 处置**，可直接照用。

---

## 1. 视图与命令位置类（Comware 7 最易错）

| # | 现象 | 原因 | 处置 |
|---|---|---|---|
| 1 | `vlan 10 11` 之后的命令全报 `Unrecognized` | **批量建 VLAN 后停留在【系统视图】**，跟 `quit` 就退回用户视图了 | 建完 VLAN 直接继续敲下一条，不要 `quit` |
| 2 | `nqa schedule` 报 Unrecognized | 它属**系统视图**命令 —— 既不能写在 `nqa entry` 里，也不能在用户视图 `<H3C>` 下敲 | 先看提示符是不是 `[H3C]`；退多了就 `system-view` 回来 |
| 3 | 紧跟 `track` 的路由报 Unrecognized | **`track` 会进入 track 子视图**（`[H3C-track-1]`） | **每条 `track` 后加 `quit`** |
| 4 | 退 `quit` 层数难以判断 | NQA 有"操作视图 → 测试类型视图"两层，不同固件落点不一致 | **每小段开头一律敲 `system-view` 兜底**（已在系统视图时无副作用）；看到 `<H3C>` 就是退过头了 |
| 5 | `reset saved-configuration` / `reboot` 报 Unrecognized | 这两条是**用户视图**命令 | 先 `quit` 逐层退回 `<设备名>`，或 `Ctrl+Z` 一步回退 |
| 6 | 对已配过类型的 NQA 组再敲 `type icmp-echo` 报一次 Unrecognized | 正常现象 | **无视**，参数照常能敲进去 |
| 7 | `jumboframe enable` 报 Unrecognized | 它是**接口级**命令，发在系统视图会报错 | 在物理口视图下发；且设备**缺省已允许 9216 字节**，本方案无需配置 |
| 8 | 首配里个别安全加固命令报 Unrecognized | 该型号/固件不支持 | **直接跳过，不影响业务配置**；想知道支持什么就在该视图敲 `?` |

## 2. 接口与端口类

| # | 现象 | 原因 | 处置 |
|---|---|---|---|
| 9 | 配 `Vlan-interface10` 报 `This subnet overlaps with another interface!` | **H3C 不允许同一设备的两个三层接口落在同一网段**。S6880 带外口若占着 `192.168.10.x`，管理网关就配不上 | 带外口改独立网段 `192.168.9.250/24` |
| 10 | 防火墙同运营商第二条线配 IP 报同样的错 | 电信两条同属 `60.191.84.160/29`、联通两条同属 `101.71.15.152/29` | **每运营商只启用一条线**；补建路径见 [04 篇 §6](./04-防火墙-F1000-AI-25.md) |
| 11 | 防火墙 WAN 口敲 `ip address` 提示命令不存在 | 部分 F1000 型号出厂只有 `GE1/0/1` 是三层口，其余电口是二层口（已加入 VLAN 1） | 先 `port link-mode route` 再配 IP。**本台实测 `GE1/0/0`–`1/0/25` 出厂即三层**，该命令属幂等保险 |
| 12 | S5120V3 敲 `interface M-GigabitEthernet0/0/0` 报 `% Wrong parameter found` | 该型号**没有带外管理口** | 管理地址配在 `Vlan-interface10`（先 `vlan 10`） |
| 13 | 万兆内网链路插了不亮 | **21 号口属 `1000BASE-X` 千兆区** | 只能用面板最右端标 `10GBASE-R` 的 **26 / 27** |
| 14 | `display vlan` 看不到成员端口 | 该命令**只列 VLAN 号**，不列成员 | 要看成员必须指定 VLAN 号：`display vlan 11`；或 `display current-configuration interface <口>` |
| 15 | 把 `HundredGigE1/0/49` 看成 `GigabitEthernet1/0/49` | `display interface brief` 会**缩写**成 `GE1/0/49` | 配置时写 `HundredGigE1/0/x`；判据 `display interface ?` |
| 16 | 光模块厂商校验告警 `A non-H3C transceiver is detected` | 第三方模块 | **只是告警，端口仍正常工作**。判据看 `display logbuffer`：只有"速率/类型与配置不匹配"才是真问题 |
| 17 | 25G 口自协商失败 | 两端速率/双工不一致 | 服务器网卡与 H3C 端口都强制 25G 全双工 |
| 18 | 链路速率不匹配 | 一端配了 `speed`、另一端没配 | 10G 链路两端都 `speed 10000`；1G 链路 S6880 侧 `speed 1000` |

## 3. 路由 / NQA / Track 类

| # | 现象 | 原因 | 处置 |
|---|---|---|---|
| 19 | `nqa entry admin ct-main` 报 `Invalid operation tag`，后续命令连环报 Unrecognized | **admin-name 与 operation-tag 都不能含连字符 `-`**（官方：1–32 字符、excluding hyphens） | 改用 `ctline` / `culine` |
| 20 | NQA 探测正常但 `display track N` 一直 `NotReady`、浮动路由不生效 | **`reaction` 的 `action-type` 缺省是 `none`**（只显示结果、不通知 Track 模块） | 必须显式写 **`action-type trigger-only`**。⚠ **联动项建好后不能改**，只能 `undo nqa entry` 删掉整条重配 |
| 21 | `next-hop` 报 Unrecognized | 本固件要求写 `next-hop ip <地址>` | 带 `ip` 关键字。**最简做法**：探测目标直接取本线路的运营商网关（在直连网段内，自动从对应接口发出），就无需配 `next-hop` / `out interface` |
| 22 | `ip route-static ... preference 60 track 1` 报 `% Too many parameters` | **关键字顺序错** | 正确：`ip route-static 0.0.0.0 0 GigabitEthernet1/0/1 60.191.84.161 **track 1** preference 60`（`track` 必须在下一跳之后、`preference` 之前） |
| 23 | `display nqa result` 无数据 | `nqa schedule` 没在系统视图下发 | 回到 `[H3C]` 重新 `nqa schedule <admin> <tag> start-time now lifetime forever` |

## 4. 安全域与策略类

| # | 现象 | 原因 | 处置 |
|---|---|---|---|
| 24 | **防火墙自己** ping 内网/公网全超时、NQA 探测全失败 | 设备自身报文属 **Local 安全域**，默认不放行 | **三个方向都要配，缺一不可**：`Local→Trust`、`Trust→Local`、**`Local→Untrust`**（漏最后一条会误判成线路/模块故障） |
| 25 | 按端口放行写了 `service tcp-443` 不生效 | 安全策略的 `service` **只接受「服务对象组名 \| any」**，不能写裸端口名 | 用 **`service-port tcp destination eq <端口>`**；**一条命令只能带一个目的端口** ⇒ 443 / 6022 拆成两条规则 |
| 26 | `nat server` 加了名字报语法错 | 该命令**没有前置名字位** | 名字（若固件支持）只能放**行尾 `rule <name>`**；不支持就省略，不影响映射 |
| 27 | NAT Server 配了但外部访问不通 | **发布 IP 不在任何接口上** ⇒ 设备不应答其 ARP | 作 **sub 地址**加到在用 WAN 口：`ip address 60.191.84.166 255.255.255.248 sub` |
| 28 | 只放行特定 TCP 端口的策略，用 `ping` 测不通 | 该策略**不放行 ICMP**，ping 必然超时 | 用对应协议/端口测：`ssh` / `Test-NetConnection -Port 22`。**不能据此判断策略无效** |

## 5. SSL VPN 类

| # | 现象 | 原因 | 处置 |
|---|---|---|---|
| 29 | `sslvpn enable` 报 Unrecognized | 本机固件（Comware 7.1.064 R8860P41）**没有这条命令** | **SSL VPN 默认可用**，由 context 的 `service enable` 控制；报错直接跳过 |
| 30 | **VPN 连上了但访问不了内网**（安全策略明明放行了） | **`filter ip-tunnel acl` 是 IP 接入的第一道过滤（按目的 IP），比安全策略更靠前**；ACL 末尾隐含 deny | 在 `acl advanced 3999` 里放行目标网段；要让运维访问设备自身，须放行 `192.168.99.0/24`。**ACL 改动即时生效，客户端无需重连** |
| 31 | 用户登不上 VPN | 漏了 **`service-type sslvpn`** | 补上（五个必配项缺一不可），`save force` |
| 32 | `display sslvpn user` 报 Unrecognized | 本固件不存在该命令 | 用 `display local-user` 或 `display sslvpn session` |
| 33 | `display local-user user-name cust01` 报 `Incomplete command` | **`user-name` 后必须跟 `class`** | 写全：`display local-user user-name cust01 class network`；或直接用不带参数的 `display local-user` |
| 34 | `display sslvpn context` 里 `Default policy group: Not configured` | 正常 | 本方案是给用户**显式绑定**策略组，不依赖默认策略组 |
| 35 | iNode 连不上 | 网关栏**只填了 IP、没带端口** | 填 `60.191.84.165:4430` |
| 36 | iNode 能连上但被踢 | 安装包不是登录页那份 | **必须从 `https://60.191.84.165:4430` 的登录页下载** |
| 37 | ssh 报 `no matching host key type found. Their offer: ssh-rsa` | 新版 OpenSSH 默认禁用 `ssh-rsa`（SHA-1），H3C 只提供该算法。**该报错说明网络已通** | ① 换 Xshell / PuTTY / MobaXterm；② 或加 `-o HostKeyAlgorithms=+ssh-rsa` |
| 38 | 客户"能连上但 ping 不通内网" | **客户端本地网段与 `192.168.10/11.x` 冲突**，VPN 下发的路由被本地抢走 | 先查客户办公网段 |
| 39 | VPN 登录后 Web 门户全空 | 属正常 —— 本方案启用 IP 接入，未配 Web 书签与 TCP 资源 | 按内网地址直接访问即可 |
| 40 | 从 VPN SSH 不到防火墙 | 防火墙自身地址属 **Local 域**，默认不从 VPN 放行 | 补 `VPN-to-Local-SSH`（只放 22）；⚠ **加之前必须先把客户口令与设备 admin 口令分离** |

## 6. 服务器与集群类

| # | 现象 | 原因 | 处置 |
|---|---|---|---|
| 41 | 多节点作业报"找不到文件" | **`/home` 各节点独立、不共享** | 一律放 `/shared`，用 `sbatch --chdir=/shared/...` 指定工作目录 |
| 42 | `slurmstepd: couldn't chdir to '/shared/scratch/$USER/...': going to /tmp instead` | **`#SBATCH` 行不做 shell 变量展开** | `--chdir` 写固定路径；变量放在脚本体内的 `cd` 里（`%j`/`%A`/`%a` 是 Slurm 自己的模板，可用） |
| 43 | `--gres=gpu:N` 一直 PENDING | 没写 `-p gpu`，落到默认的 `cpu` 分区（**无 GPU**） | 显式 `-p gpu` |
| 44 | `slurmdbd` 反复 fatal、6819 不监听、`sacct` 连不上 | **`slurmdbd.conf` 的 `DbdHost` 没跟着主机名一起改** | `sed -i 's/^DbdHost=.*/DbdHost=mgmt01/' /etc/slurm/slurmdbd.conf` 后 `systemctl restart slurmdbd`（**改 `slurm.conf` 时最容易漏这个文件**） |
| 45 | `srun` 报 `Unable to allocate resources` / `missing node master in job credential`（而 `sinfo` 看着正常） | slurmctld 状态文件 `part_state` 残留**旧节点名** | 停 slurmctld → 备份并删除 `node_state`、`part_state`、`*.old`、`dbd.messages` → 启动（节点会自动重新注册） |
| 46 | 节点看着 idle 但作业卡在 `COMPLETING` | 用了 `systemctl try-restart`，**进程没真正重启** | 用 **`systemctl restart`**；判据 `scontrol show node X \| grep SlurmdStartTime` **有值**（`None` = 从未成功注册） |
| 47 | mgmt01 / stg01 的作业异常 | 两台**同时是计算节点**，按角色写脚本时漏重启了它们的 `slurmd` | **每台都重启 `slurmd`**，控制端再额外重启 `slurmdbd` + `slurmctld` |
| 48 | 开机掉 emergency / NFS 未挂上 | fstab 缺 `nofail,_netdev,bg` | 补上；先重启 stg01 再客户端 |
| 49 | slurmdbd 无法加载 mysql 插件 | 编译时 `--with-mysql_config` 传了**单文件** | 传**目录** `/usr/bin`；cgroup 插件需 `--enable-cgroupv2=yes` |
| 50 | slurmd 打不开，报 `libhwloc.so.15` 缺失 | 目标节点缺库 | `sudo apt-get install -y libhwloc15 libnuma1 libjson-c5` |
| 51 | `sacctmgr -i add account` 报 `Only admins/operators/coordinators can add accounts` | 非 SlurmDBD admin | **必须 `sudo`**（以 root 执行） |
| 52 | tmpfiles 报 `Invalid age '-nd'` | 配置文件被写成单行（`printf '%s'` 写入了字面量 `\n`） | 用 here-doc **真实换行**重写 |
| 53 | 普通用户写 `/shared` 失败 | 根目录 `root:root 755`（只读） | 用 `/shared/scratch`、`/shared/slurm-logs`（`ps:ps 770`） |
| 54 | 分区 `Nodes=gpu01-08` 解析异常 | 区间写法不被支持 | **显式列举** `gpu01,gpu02,...,gpu08` |
| 55 | 新 GPU 节点首次 slurmd 报 `cpu cgroup controller is not available` | 启动竞态 | 不需处理，`Restart=on-failure` 会自动重试自愈 |
| 56 | 作业被杀、`sacct` 显示 `OUT_OF_MEMORY` | `CR_Core_Memory` 严格受限，实际用超申请值 | 把 `--mem` **按峰值**报足 |
| 57 | 主机名同名解析到新旧两个地址 | `/etc/hosts` 混入旧网段/旧主机名 | 删含旧主机名与 `192.168.18/19/20.x` 的行，写入全集，顺手修 `127.0.1.1` |
| 58 | `chronyc sources` 显示 `^? master` | 客户端仍指向旧名 | 改 `server mgmt01 iburst`，等 1–2 分钟看 `chronyc tracking` 的 `Leap status` 为 `Normal` |
| 59 | netplan 报 unknown key `ibs` | netplan 没有该顶层关键字 | IPoIB 口放进 `ethernets:` 段，用 `infiniband-mode` 指定（本项目不需要配） |

| 61 | `CLUSTER ID MISMATCH` | 启用记账后 slurmctld 起不来 | `rm -f /var/spool/slurm/ctld/clustername` 后重启（以 DB 为准） |

## 7. 现场操作类

| # | 现象 | 原因 | 处置 |
|---|---|---|---|
| 62 | 粘贴的配置"完全没进去"，最后报 `Login:` / `AAA authentication failed` | **Console 串口会话中途掉线会吃掉正在粘贴的配置**；屏上会重现 `Line aux0/con0 is available` + `Press ENTER to get started` | **一次粘 ≤10–15 行**；每段敲完 `display current-configuration` 或看提示符确认；掉线后**从断点重敲** |
| 63 | ssh 报 `Connection timed out` | TCP 根本没到设备。**最常见：笔记本只连 Wi-Fi（含手机热点）而没插网线** —— 笔记本上没有该网段路由，请求被交给 Wi-Fi 网关发走了 | 插网线直连设备管理口；笔记本 IP 手配同网段、**网关留空**；先 `ping` 再 `ssh`；查 `display ip interface <口>` 的 `Line protocol state` |
| 64 | 单机形态下误敲了 `irf` 命令 | 一期不堆叠 | 只要**没有 `save force`**，`reboot` 即回滚 |
| 65 | 恢复出厂设置怎么按 | `reset saved-configuration` 与 `reboot` **都是用户视图命令** | 流程：`reset` → Y → `reboot` → "save?"答 **N**（答 Y 白清）→ "Continue?"答 Y。**必须在 Console 做，先备份** |

## 8. 四套排障流程

### 8.1 ssh 到设备超时

```
1. 网线是否直插这台设备的管理口（不是业务口、不是别的交换机）
   ⚠ 笔记本不插网线必然 timeout
2. 笔记本 IP：直连 M-GE 用 192.168.9.100/24（网关留空）；接管理网用 192.168.10.x
   ipconfig 确认；同时连着 Wi-Fi 就先禁用 Wi-Fi
3. 先 ping 后 ssh：ping 192.168.9.250（或 192.168.10.254）
   通了但 ssh 超时 → Console 查 display ssh server status
   不通 → 回到第 1、2 步
4. 设备侧口状态：display interface M-GigabitEthernet0/0/0 看 Line protocol state: UP
```
判据速记：`Permission denied` = 已连上（密码错）；`Connection refused` = SSH 服务没开；`timeout` = 包没到。

### 8.2 服务器"网卡 up 但上不了网"

```
1. S6880 上 display interface brief → 找出 UP 的那个口
2. display vlan → 看这个口属于哪个 VLAN
   ⚠ 只有 1/0/1–1/0/12 是 access VLAN 11；1/0/13–1/0/46 属 VLAN 1（没有网关）
3. 不在 VLAN 11 → 换口，或把该口划进来：
   interface <该接口全名>
    port link-type access
    port access vlan 11
4. 再 ping 192.168.11.254 → 通则网关 OK；ping 223.5.5.5 → 通则出口 NAT OK
   （不通再查防火墙 ACL 3000 与 nat outbound）
```

### 8.3 VPN 连上但访问不了内网

```
1. 先看第一道过滤：acl advanced 3999 是否 permit 了目标网段（⚠ 比安全策略更靠前）
2. 再看安全策略：display security-policy ip（VPN→Trust 的对应端口规则）
3. 再看回程：S6880 与 S5120V3 是否各有 ip route-static 192.168.99.0 24
4. 最后看物理链路：Vlan-if10 / Vlan-if11 是否 up（这是最常见根因）
5. 客户端侧：route print 是否有两条内网路由；本地网段是否冲突
```

### 8.4 IB 起不来 / 带宽异常

```
1. ibstat -l → 确认本机 IB 卡设备号（mgmt01=mlx5_0；gpu/stg=mlx5_2）
2. mlxconfig -d /dev/mst/mt4123_pciconf0 q → LINK_TYPE_P1 是否为 1（IB）
3. ibstat → State 是否 Active、Rate 是否 200
4. 线缆是否 NVIDIA 认证 HDR 型号
5. sminfo → 是否有且仅有一个 SM（无双 SM 抢权）
6. ib_write_bw --report_gbits <对端> → ≥ 190 为正常（实测 196.83）
```

### 8.5 作业提交后 PENDING

```bash
squeue -j <JobID> -o "%.18i %.9P %.8j %.2u %.2t %.10M %.6D %R"
```

| REASON | 含义 | 处理 |
|---|---|---|
| `Priority` | 有更高优先级作业在前面 | 等待，或 `sprio -j <JobID>` 看差距 |
| `Resources` | 资源暂时不够 | 等，或降低 `-c` / `--mem` / `--gres` |
| `ReqNodeNotAvail` | 指定节点不可用 | 去掉 `-w` 或换节点 |
| `PartitionNodeLimit` / `PartitionTimeLimit` | 超出分区限制 | 检查 `-N` 与时限 |
| `Dependency` | 上游作业未完成 | `scontrol show job` 看依赖 |
| `None` | 可以立即运行 | — |

> **最常见原因**：GPU 要多了（`--gres=gpu:8` 却只想用一张）、内存要超了（`--mem=1000G` 但单节点上限 1000G）。

## 9. 快速回退表

| 故障 | 处置 |
|---|---|
| 单机形态下误敲了 `irf` 命令 | 单台不需要堆叠命令；`irf member 1 renumber` 这类改动只要没有 `save force`，`reboot` 即回滚 |
| 某阶段配置敲错 | `save` 之前的错误可重启回滚；已保存则进入对应接口 `undo` 逐条撤销 |
| 防火墙 WAN 口配 `ip address` 提示命令不存在 | 该口仍是二层模式；先 `port link-mode route` |
| 防火墙切到备线不回切 | `display track all` 看状态；NQA 失败多为 `action-type` 未写 `trigger-only`，或 `nqa schedule` 没在系统视图下发 |
| NAT Server 生效但外部访问不通 | 安全策略里 `service` 写成了裸端口名；改用 `service-port tcp destination eq <端口>` |
| 大帧命令报 Unrecognized | `jumboframe enable` 发在了系统视图（接口级命令，且默认已允许 9216 字节） |
| 配置丢失 | 单机无设备级冗余 —— 从离线备份恢复；平时每阶段 `save force` |
| 交换机端口配置乱了 | `display current-configuration interface <口>` 看现状，逐条 `undo`；必要时 `reset saved-configuration` + `reboot`（先备份！） |
| 服务器网络配置改坏 | 改前 `cp /etc/netplan/xxx.yaml xxx.yaml.bak`；用 `netplan try`（30 秒不确认自动回滚） |
| 主机名/hosts 改坏导致集群异常 | 见 [05 篇 §6.3](./05-服务器与集群服务.md) 的清理三步：`slurmdbd.conf` 的 `DbdHost`、清 `part_state`、每台 `systemctl restart slurmd` |
