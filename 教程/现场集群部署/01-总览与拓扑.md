# 01 · 总览与拓扑

> 本篇回答：**这套集群长什么样、每台设备干什么、线怎么连、地址怎么分**。
> 逐设备的配置命令见 02–07；按顺序施工见 08；判据见 09。

---

## 1. 系统定位与设计目标

一套部署在**单一机房**内的 HPC 算力集群，面向 GPU 训练/推理与并行计算负载，同时需要**对外开放**（对外发布 Web 服务）与**对外授权使用**（异地客户远程使用机器）。

设计上要同时满足五件事：

| # | 目标 | 落地手段 |
|---|---|---|
| 1 | 管理与业务流量隔离 | 双 VLAN：VLAN 10 = 带外管理（BMC），VLAN 11 = 业务（含存储前端） |
| 2 | 出口不中断 | 双运营商（电信 + 联通）浮动路由主备，NQA 探测 + Track 联动自动切换 |
| 3 | 内网出口与入站可控 | NAT outbound（Easy-IP）出方向 + NAT Server 精确端口发布入方向 |
| 4 | 异地客户可"管理 + 使用" | SSL VPN **IP 接入**，下发管理网 + 业务网两个网段路由 |
| 5 | 计算通信高性能 | 独立 200G InfiniBand fabric，与以太网完全物理隔离 |

## 7. 典型数据流向

### 7.1 内网 → 公网（出方向 NAT）

```
服务器/BMC → S6880(Vlan-if10/11 三层网关) → 默认路由 0.0.0.0/0 指向 192.168.254.1
          → 防火墙命中 ACL 3000 → nat outbound（Easy-IP，源地址转成在用 WAN 口地址）
          → 命中缺省路由 pref 60（电信）或 70（联通）→ 公网
```

### 7.2 公网 → 内网（入方向 NAT Server）

```
外部访问 https://60.191.84.166:443
   → 运营商 → 防火墙 GE1/0/1（持有 .166 的 sub 地址）
   → NAT Server 命中：60.191.84.166:443 → 192.168.11.11:443
   → 安全策略 WAN-to-Platform-443 放行 → 转给 S6880 → 平台服务
   （响应按会话原路返回，不需额外策略路由）
```

### 7.3 异地客户 → 内网（SSL VPN）

```
iNode 客户端（拿到 192.168.99.x）
   → 公网 60.191.84.165:4430 → SSL 网关 remotegw
   → ACL 3999（第一道过滤：只允许目的 192.168.10.0/24、192.168.11.0/24、（可选）192.168.99.0/24）
   → 安全策略（第二道过滤：按安全域 + 端口）
   → VPN → Trust：管理网 443/22/623、业务网全端口
   → 转发给 S6880 → 服务器业务口 / 服务器 BMC
   回程：S6880 有 ip route-static 192.168.99.0/24 → 192.168.254.1；S5120V3 有一条指向 192.168.10.254
```

### 7.4 计算通信（IB）

```
gpuXX 作业 → MPI/NCCL → UCX → IB verbs（rc_mlx5 / dc_mlx5）→ MQM8790 fabric → gpuYY
（不经 IP、不经以太网、不走 IPoIB；Slurm 调度与 NFS 仍走 25G 业务网）
```

## 8. 设计原则（七条）

1. **三层网关收敛在业务交换机** —— S6880 单机作为全网唯一三层网关（Vlan-if10 / Vlan-if11），防火墙只做出口路由 + NAT + 策略。**单机形态没有设备级冗余**，因此每个阶段结束都 `save force`。
2. **管理网不直连防火墙** —— BMC/带外网段经 trunk → S6880 → 防火墙访问外网，中间必须过网关，便于统一控制。
3. **算力网物理隔离** —— IB fabric 独立组建，无以太网网关、无跨网路径；PKey（Partition）用于逻辑隔离计算与存储流量（**当前单平面未实施，见 06 篇**）。
4. **双运营商主备出口** —— 浮动静态路由 + Track/NQA 探测 + 出接口 Easy-IP NAT。因同网段限制，本期退化为**运营商级**主备（电信 60 → 联通 70），同运营商内部两线冗余未启用。
5. **每个 VLAN 一段统一配置、不绑定具体节点** —— 交换机下联口只按 access VLAN 划分，节点换插口只需换线，交换机零改动。
6. **管理与计算分离** —— Slurm 管理面与 NFS 走 25G 业务网（不依赖 IB 的 SM）；IB 只留给 MPI/NCCL 计算通信。这样任一侧升级都不影响另一侧。
7. **命令与文档同源** —— 所有命令语法均按 H3C Comware 7 / NVIDIA Onyx 官方参考核对过，现场踩到的差异（视图层级、参数顺序、端口名）全部回写进文档。
