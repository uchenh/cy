## 2. 技术基线（三份一致）

| 项 | 取值 |
|----|------|
| 发行版 | Ubuntu 24.04 LTS（noble） |
| 内核 | **6.8 GA 线**（如 6.8.0-138-generic，`apt-mark hold` 锁定；禁用 HWE 7.0） |
| Lustre | **2.17.0**（b2_17 分支 / commit 4b0407a，服务端源码编译 `make debs`） |
| 存储后端 | **ZFS 2.2.2**（Ubuntu 自带，零内核补丁；`--with-zfs --disable-ldiskfs`） |
| 网络 | LNet `@tcp`（端口 988），NID = 本机 IP |
| 形态 | All-in-One：MGS/MDS/OSS/Client 全部一台，官方支持 |

**部署流程（8 步，三份通用）**：内核修正 → 基础环境（chrony/工具/关 swap）→ ZFS+编译依赖 → 服务端源码编译（约 40 分钟，走代理）→ 安装 deb+LNet → 建池+mkfs（MGT/MDT/OST0/OST1）→ 客户端挂载 → 开机自启（fstab+cachefile+systemd）。

## 3. 配置对照（09 生产档 vs 10 实验档）

| 项 | 09 生产档 | 10/11 实验档 |
|----|-----------|--------------|
| CPU | 8~16 核 ≥3.5GHz | 2~4 vCPU |
| 内存 | 32~64 GB ECC（ZFS ARC 占 50%） | 4~8 GB |
| 系统盘 | 480G SSD（可 RAID1） | 50G |
| MGT | 16G NVMe 独立 | 1~2G 盘 |
| MDT | 500G~1T **NVMe**（随机 4K 小 IO） | 10~20G 盘 |
| OST | 2~4 块 × 2~4TB，**mirror/RAID-Z**（生产绝不单盘） | 20G×2 裸盘 |
| 网络 | 10GbE+，优先 RoCE/IB | 1GbE 足够 |

> 单机 All-in-One 无法满足生产的高可用与组件隔离（单点、资源共享）；生产形态参考见 09 §2（MGS+MDS 双机 HA、OSS 集群）。

## 4. 实测结果（11：192.168.12.160，2026-08-26）

| 验证项 | 结果 |
|--------|------|
| 内核 / Lustre / ZFS | 6.8.0-138（GA，hold）/ 2.17.0 / 2.2.2 |
| LNet | `192.168.12.160@tcp` up |
| 目标 | MGS / MDT0000 / OST0000 / OST0001 全部注册，`lctl dl` 24 项 UP |
| 容量 | MDT 18.7G + OST0 38.0G + OST1 28.4G = **66.3G** |
| 条带化 | `-c 2` 生效，文件横跨 OST0000/0001 |
| IO | dd 512M = 167 MB/s（VM 本机回环） |
| 重启自愈 | zpool 自动导入、目标自动挂载、客户端 15s 内恢复 |

## 5. 关键教训（实测沉淀）

1. **磁盘设备名漂移**：内核切换/重启后 `/dev/sdX` 可能互换（实测 sdb↔sdc、sdd↔sde），建池前必须重新 `lsblk` 确认；**生产用 `/dev/disk/by-id/` 建池**。池创建后 vdev 绑定设备内部 ID，后续重启不受影响。
2. **内核顺序**：必须先切 6.8 GA 并 purge 7.0 HWE，再装 ZFS；顺序反了 `zfs-dkms` 编译卡死（dpkg 锁被占）。
3. **客户端挂载**：fstab `_netdev` 不等 MGS recovery，重启会丢挂载；用"先 ping MGS 直到可达再 mount"的等待式 systemd。
4. **单机 recovery 窗口**：重启后 OST 进入 recovery（默认最长 5 分钟），期间 `lfs df` 暂缺该 OST，等窗口结束自动恢复——正常现象。
5. **sudo 路径**：sudo 下 `~` = `/root`，涉及 `~` 的命令用绝对路径；`systemctl reboot` 比 `reboot` 可靠。
6. **MDT 偏小可重建**：MDT 只有 2G 时，销毁四池按正确盘符重建即可（实验环境数据量小，10 分钟完成）。
