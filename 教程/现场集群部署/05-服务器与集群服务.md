## 2. 硬件、BIOS 与固件要点（装机时统一设置）

| 项目 | 设置 | 原因 |
|---|---|---|
| 性能模式 | Power Determinism = Power、性能模式 High | EPYC 满频，避免降频抖动 |
| NUMA | NPS1（或按 NCCL 实测调 NPS4） | 8 卡 A100 跨 NUMA 通信调优 |
| Above 4G Decoding / Resizable BAR | 开启 | 8×A100 80G 必需，否则部分卡初始化失败 |
| PCIe 链路 | 装机后逐卡核对 Gen4 x16 | A100 PCIe 性能依赖链路满速 |
| RAID 卡 | 见 §8 存储架构 | 存储节点走 JBOD/直通是设计目标 |
| BMC | 固件升级 + 配 VLAN 10 地址、网关 192.168.10.254 | 带外管理统一 |
| Swap | **关闭**（`swapoff -a` + 从 fstab 删除 + mask swap 单元） | 避免作业被换出、内存约束失效 |
| RTC | `timedatectl set-local-rtc 0`（统一 UTC） | 集群时间一致性 |

### 2.1 磁盘规划

## 4. 业务口网络（VLAN 11）

### 4.1 单口（当前形态）

> 交换机侧**未做聚合** ⇒ 服务器侧**不要写 bond0**，直接给单块网卡配 IP。

`/etc/netplan/01-net.yaml`（模板只有网卡名与 `addresses` 每台不同）：

```yaml
network:
  version: 2
  ethernets:
    enp1s0f0:                                  # ← 换成 `ip link` 查到的实际网卡名
      addresses: [192.168.11.11/24]            # ← 按下表
      routes: [{ to: default, via: 192.168.11.254 }]
      nameservers: { addresses: [223.5.5.5, 114.114.114.114] }
```

| 节点 | 地址 | 接 S6880 | 节点 | 地址 | 接 S6880 |
|---|---|---|---|---|---|
| mgmt01 | 192.168.11.11 | `1/0/1` | gpu04 | 192.168.11.16 | `1/0/6` |
| stg01 | 192.168.11.12 | `1/0/2` | gpu05 | 192.168.11.17 | `1/0/7` |
| gpu01 | 192.168.11.13 | `1/0/3` | gpu06 | 192.168.11.18 | `1/0/8` |
| gpu02 | 192.168.11.14 | `1/0/4` | gpu07 | 192.168.11.19 | `1/0/9` |
| gpu03 | 192.168.11.15 | `1/0/5` | gpu08 | 192.168.11.20 | `1/0/10` |

应用与验证：

```bash
sudo netplan try            # 30 秒内不确认会自动回滚，改错也不会断网
sudo netplan apply
ip -br addr show            # 业务网卡 up、地址生效
ping -c3 192.168.11.254     # 通 = 网关 OK
ping -c3 223.5.5.5          # 通 = 出口 NAT OK
```

> - `stg01` 若不想让存储前端走默认路由，删除 `routes` 行即可（不影响本网段互访）。
> - MTU 建议初版保持 **1500**。如确要压到 9000，必须**服务器业务口 / S6880 下联口 / stg01 挂载端同时改**，缺一个不通。（S6880 侧缺省已允许 9216 字节，一般无需配置。）

### 4.2 双口 LACP 聚合（后续启用，两端同步改）

交换机侧先建聚合口并接上第二根线，服务器侧改为：

```yaml
network:
  version: 2
  bonds:
    bond0:
      interfaces: [enp1s0f0, enp1s0f1]
      parameters: { mode: 802.3ad, lacp-rate: fast, mii-monitor-interval: 100 }
      addresses: [192.168.11.11/24]
      routes: [{ to: default, via: 192.168.11.254 }]
      nameservers: { addresses: [223.5.5.5, 114.114.114.114] }
```

```bash
sudo netplan apply
cat /proc/net/bonding/bond0     # 两口均 up、Current policy: 802.3ad
```

> ⚠ **两端必须同时改**：只改服务器侧 → bond0 协商不上、断网；只改交换机侧 → 第二口 down。建议维护窗口内一次做完。

### 4.3 IPoIB（规划值，**本项目未配置且不需要**）

| 节点 | IB 口1 | IB 口2 |
|---|---|---|
| mgmt01 | 10.20.1.10 | 10.20.2.10 |
| gpu01–08 | 10.20.1.11–18 | 10.20.2.11–18 |
| stg01 | 10.20.1.20 | 10.20.2.20 |

如需启用（本方案不需要，MPI/NCCL 走 verbs 直通）：

```yaml
# ⚠ netplan 没有 `ibs:` 顶层关键字（写了报 unknown key，整段不生效）
#   IPoIB 口要放进 ethernets: 段，用 infiniband-mode 指定传输模式
network:
  version: 2
  renderer: networkd
  ethernets:
    ibp129s0f1:
      addresses: [10.20.1.10/16]
      infiniband-mode: connected      # connected=RC（MTU 大）；datagram=UD（默认）
    ibp129s0f2:
      addresses: [10.20.2.10/16]
      infiniband-mode: connected      # 单口卡删掉本节
```

> ⚠ **IB 口名因机而异**：mgmt01 = `ibs2f0`、gpu01 = `ibP1p129s0f0`。**先 `ip link` 查，不要想当然写 `ib0`。**

## 5. BMC 带外管理（VLAN 10）

### 5.1 配置（两种方式任选）

**网页**（推荐）：办公电脑接管理网 → 浏览器 **`https://192.168.10.<尾号>`** → 登录 → Network 设置 IP/掩码/网关。

**ipmitool**：

```bash
sudo apt install -y ipmitool
sudo ipmitool lan set 1 ipsrc static
sudo ipmitool lan set 1 ipaddr 192.168.10.11
sudo ipmitool lan set 1 netmask 255.255.255.0
sudo ipmitool lan set 1 defgw ipaddr 192.168.10.254
```

| 节点 | BMC IP | 接 S5120V3 | 节点 | BMC IP | 接 S5120V3 |
|---|---|---|---|---|---|
| mgmt01 | 192.168.10.11 | `GE1/0/1` | gpu04 | 192.168.10.16 | `GE1/0/6` |
| stg01 | 192.168.10.12 | `GE1/0/2` | gpu05 | 192.168.10.17 | `GE1/0/7` |
| gpu01 | 192.168.10.13 | `GE1/0/3` | gpu06 | 192.168.10.18 | `GE1/0/8` |
| gpu02 | 192.168.10.14 | `GE1/0/4` | gpu07 | 192.168.10.19 | `GE1/0/9` |
| gpu03 | 192.168.10.15 | `GE1/0/5` | gpu08 | 192.168.10.20 | `GE1/0/10` |

### 5.2 三个必须注意的点

| # | 点 | 说明 |
|---|---|---|
| 1 | **BMC 侧不要配 VLAN** | S5120V3 的 `GE1/0/1–10` 是 **access VLAN 10**（交换机侧打标、发出去已剥标）。BMC 上再填 VLAN ID 会变成带标帧，access 口直接丢弃 —— 表现为「地址配了但 ping 不通」。ipmitool 对应 `lan set 1 vlan id off` |
| 2 | **地址栏必须带 `https://`** | 只输 `192.168.10.11` 浏览器会补成 `http://`（80 端口），而 BMC 界面在 **443**；且从 VPN 访问时安全策略只放行 443、未放行 80 ⇒ 必然打不开 |
| 3 | **首次访问有自签证书告警** | 选「继续访问」即可；建议把 10 个 `https://192.168.10.x` 存成书签 |

### 5.3 网关

BMC 网关 = **192.168.10.254**（S6880 的 `Vlan-if10`）。BMC 上网路径：`BMC → S5120V3 → trunk → S6880（Vlan-if10 网关）→ 防火墙`。

### 5.4 ⏳ 待办：BMC 默认口令

| 节点 | 账号 | 初始口令 |
|---|---|---|
| mgmt01 | admin | `admin#254` |
| stg01 / gpu01–08 | admin | **`admin`**（默认口令） |

## 6. 主机名与 `/etc/hosts`

### 6.1 主机名规则（固定写法）

`mgmt01`、`stg01`、`gpu01`–`gpu08` —— **gpu 用两位数字**（不是 `gpu1`）；`mgmt01`/`stg01` **不再追加其他数字**。

```bash
sudo hostnamectl set-hostname gpu01 && hostname
```

> ⚠ 主机名必须与 `slurm.conf` 的 `NodeName` **完全一致**，否则 slurmd 无法注册。
> 改名后当前 SSH 会话提示符不会立刻变（`exec bash` 或重登）；**若用旧名 ssh 进来，改完必须用新名重连**。

### 6.2 `/etc/hosts`（每台写同一份全集）

> **只写业务网（`192.168.11.x`）** —— Slurm 与 NFS 都基于主机名解析，走 25G 业务网即可。
> **不写管理网（`192.168.10.x`）、不写 IPoIB。** BMC 地址不进 hosts。

```
127.0.0.1   localhost
192.168.11.11 mgmt01
192.168.11.12 stg01
192.168.11.13 gpu01
192.168.11.14 gpu02
192.168.11.15 gpu03
192.168.11.16 gpu04
192.168.11.17 gpu05
192.168.11.18 gpu06
192.168.11.19 gpu07
192.168.11.20 gpu08
```

**先清旧残留再加**（否则同一主机名可能同时解析到新旧两个地址）：

```bash
sudo cp /etc/hosts /etc/hosts.bak.$(date +%F)
sudo sed -i -E '/\b(master|storage|gpu[1-9][0-9]?)\b/Id; /192\.168\.(18|19|20)\./d' /etc/hosts
# 再追加上面的 10 行；顺手把 127.0.1.1 改成当前主机名
```

下发：在 mgmt01 上 `for h in ...; do scp /etc/hosts $h:/etc/hosts; done`（需先配好 SSH 免密）。

## 7. 集群服务部署

> 一键脚本：`docs/10台服务器/setup-node.sh`（**幂等**）把下面的基础环境 + chrony + NFS + 服务重启一次做完：
> `sudo bash setup-node.sh <本机名>`，**stg01 必须最先执行**（它是 NFS 服务端）。

### 7.1 基础环境（每台）

```bash
# 关防火墙 + 提 limits
sudo systemctl stop ufw; sudo systemctl disable ufw; sudo iptables -F
printf '* soft nofile 65535\n* hard nofile 65535\n* soft nproc 65535\n* hard nproc 65535\n' | sudo tee -a /etc/security/limits.conf

# 关闭 swap
sudo swapoff -a
sudo sed -i '\#/swapfile#d' /etc/fstab
sudo systemctl mask '*.swap'
```

### 7.2 时间同步 chrony

```bash
sudo apt-get update -y && sudo apt-get install -y chrony
```

**mgmt01（NTP 源）** `/etc/chrony/chrony.conf`：

```
pool ntp.ubuntu.com iburst
allow 192.168.11.0/24
local stratum 10
```

**stg01 / gpu01-08（客户端）**：

```
server mgmt01 iburst
```

```bash
sudo systemctl restart chrony; sleep 3
chronyc sources | head                    # 客户端应看到 ^* mgmt01
sudo timedatectl set-local-rtc 0          # RTC 统一 UTC
```

> ⚠ 改主机名后若 `chronyc sources` 显示 `^? master`、`Not synchronised`，说明客户端还指向旧名，改 `server mgmt01 iburst` 后等 1–2 分钟看 `chronyc tracking` 的 `Leap status` 应为 `Normal`。

### 7.3 NFS 共享（220T）

**stg01 服务端**：

```bash
sudo apt-get install -y nfs-kernel-server
sudo mkdir -p /mnt/sdb/home /mnt/sdb/slurm-logs /mnt/sdb/scratch
sudo chown ps:ps /mnt/sdb/slurm-logs /mnt/sdb/scratch && sudo chmod 770 /mnt/sdb/slurm-logs /mnt/sdb/scratch
echo '/mnt/sdb 192.168.11.0/24(rw,sync,no_root_squash,no_subtree_check)' | sudo tee -a /etc/exports
sudo exportfs -ra && sudo systemctl enable --now nfs-server && sudo exportfs -v
```

> `slurm-logs` = 作业输出统一落点、`scratch` = 普通用户临时共享区（均 `ps:ps 770`）。
> **`exports` 已由 `*` 收紧为 `192.168.11.0/24`**。
> stg01 本机 `/shared` 用 **bind mount** 到阵列，保证 10 台路径一致。

**客户端（mgmt01 + gpu01–08，共 9 台）**：

```bash
sudo apt-get install -y nfs-common
sudo mkdir -p /shared
echo 'stg01:/mnt/sdb /shared nfs defaults,nofail,_netdev,bg,hard,intr,x-systemd.mount-timeout=30 0 0' | sudo tee -a /etc/fstab
sudo mount -a
df -hT | grep /shared          # 应见 stg01:/mnt/sdb 220T
```

> ⚠ 必须 `nofail,_netdev,bg`，否则开机 NFS 未就绪会掉 emergency。
> ⚠ 挂载源写**主机名 `stg01`**（解析到 192.168.11.12）⇒ 走 25G 业务网，与 Slurm 同链路。
> 验证：`touch /shared/.probe-$(hostname) && ls /shared` 交叉确认。

### 7.4 MUNGE 认证（每台共享同一把 key）

```bash
# 每台
sudo apt-get install -y munge libmunge-dev libmunge2
sudo mkdir -p /var/lib/munge /run/munge /var/log/munge /etc/munge
sudo chown -R munge:munge /var/lib/munge /run/munge /var/log/munge /etc/munge

# mgmt01 生成密钥，记下 base64 串
sudo dd if=/dev/urandom of=/etc/munge/munge.key bs=1024 count=1 status=none
sudo chown munge:munge /etc/munge/munge.key; sudo chmod 400 /etc/munge/munge.key
sudo base64 -w0 /etc/munge/munge.key

# 其余 9 台写入同一密钥
echo 'KEYB64' | base64 -d | sudo tee /etc/munge/munge.key >/dev/null
sudo chown munge:munge /etc/munge/munge.key; sudo chmod 400 /etc/munge/munge.key

# 启动与校验
sudo systemctl enable munge && sudo systemctl restart munge     # 服务名 munge.service
sha256sum /etc/munge/munge.key | awk '{print $1}'               # 10 台应完全一致
echo 'test' | munge -n | unmunge 2>&1 | grep STATUS             # -> Success
```

### 7.5 Slurm 24.11.6 编译与分发（mgmt01）

```bash
sudo apt-get install -y build-essential gcc make hwloc libhwloc-dev libmunge-dev libssl-dev \
  libcurl4-openssl-dev libjson-c-dev liblua5.3-dev libdbus-1-dev libbpf-dev libelf-dev \
  linux-libc-dev pkg-config libmariadb-dev libmariadb-dev-compat

mkdir -p /opt/slurm-build && cd /opt/slurm-build
curl -fL --retry 3 -o slurm-24.11.6.tar.bz2 https://download.schedmd.com/slurm/slurm-24.11.6.tar.bz2
tar xjf slurm-24.11.6.tar.bz2 && cd slurm-24.11.6
./configure --prefix=/usr/local --sysconfdir=/etc/slurm --datarootdir=/usr/local/share \
  --with-munge --with-hwloc --enable-cgroupv2=yes --with-mysql_config=/usr/bin
make -j$(nproc) && sudo make install
```

> ⚠ `--with-mysql_config=/usr/bin` 必须是**目录**（传单文件仍不带 mysql 插件）；`--enable-cgroupv2=yes` 才产出 `cgroup_v2.so`。**两个插件缺失会导致 slurmd / slurmdbd 启动失败。**

分发（大包必须 **scp/SFTP 直传**，base64 分发会卡住）：

```bash
sudo tar czf /tmp/slurm_usr_local.tgz -C / /usr/local     # 约 129M
scp /tmp/slurm_usr_local.tgz ps@stg01:/tmp/               # 同理 gpu01–08
# 各目标节点
cd / && sudo tar xzf /tmp/slurm_usr_local.tgz -C /
echo '/usr/local/lib' | sudo tee /etc/ld.so.conf.d/slurm.conf && sudo ldconfig
/usr/local/sbin/slurmd -V                                 # -> slurm 24.11.6
```

## 8. 存储架构（⚠ 现状与设计不一致）

## 11. 本篇相关坑（详见 [11-附录B](./11-附录B-现场坑与排障.md)）

1. **`/home` 各节点独立、不共享** —— 跨机器文件一律放 `/shared`。
2. **`#SBATCH` 行不做 shell 变量展开** —— `--chdir=/shared/scratch/$USER` 会 fallback 到 `/tmp` 并报 `couldn't chdir`。
3. 不写 `-p` 会落到默认 `cpu` 分区（无 GPU），`--gres=gpu:N` 会一直 PENDING。
4. `slurmdbd.conf` 的 `DbdHost` 忘改 → slurmdbd 反复 fatal、6819 不监听、记账不可用。
5. slurmctld 状态文件 `part_state` 残留旧节点名 → `srun` 报 `Invalid node name`（而 `sinfo` 看着正常）。
6. `systemctl try-restart` 不保证重启 → 用 **`restart`**；判据 `scontrol show node X` 的 `SlurmdStartTime` 不为 `None`。
7. mgmt01/stg01 同时是计算节点，**slurmd 不能漏重启**。
8. NFS 缺 `nofail,_netdev,bg` → 开机掉 emergency。
9. `--with-mysql_config` 传单文件 → 仍不带 mysql 插件。
10. `sacctmgr` 不加 `sudo` → `Only admins can add accounts`。
11. tmpfiles 写成单行 → `Invalid age '-nd'`。
12. 普通用户写 `/shared` 根目录失败（`root:root 755`）→ 用 `/shared/scratch`。
13. 分区 `Nodes=gpu01-08` 区间写法解析异常 → 显式列举。
14. 缺 `libhwloc.so.15` → `apt-get install libhwloc15 libnuma1`。
